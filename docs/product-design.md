# Boss Auto 产品设计

## 1. 产品概述

Boss Auto 是面向 Boss 直聘的求职自动化辅助工具，帮助用户筛选职位、执行“立即沟通”，并根据预设模板自动回复招聘者。

当前包含三个核心页面：

1. 职位列表页
2. 聊天沟通页
3. 设置页面

设置页面以全屏配置视图的形式打开，不是独立网址页面。

## 1.1 配置版本

用户可以创建多套独立的配置版本，并在使用前进行切换。每个版本保存一整套求职自动化配置，包括：

- 职位关键词
- 工作地点
- 屏蔽词
- 招聘者在线状态筛选规则
- 无法识别在线状态时的处理方式
- 多轮聊天文字消息
- 图片消息及消息发送顺序

版本切换后，职位列表页和聊天沟通页均使用当前选中的版本。

## 2. 职位列表页

### 页面目标

按照用户的职位偏好自动筛选职位，并批量执行“立即沟通”操作。

### 页面功能

- 当前配置版本展示：显示当前正在使用的配置版本名称。
- 配置版本切换：可在职位页快速切换已保存的配置版本。
- 职位关键词筛选：读取当前配置版本中的职位关键词；职位页仅展示，不直接编辑。
- 工作地点筛选：读取当前配置版本中的城市或远程办公条件；职位页仅展示，不直接编辑。
- 屏蔽词筛选：读取当前配置版本中的屏蔽词；职位页仅展示，不直接编辑。
- 职位信息采集：读取职位名称、薪资、公司、地点和职位标签。
- 自动滚动与翻页：加载更多职位并建立待处理职位队列。
- 去重处理：根据职位链接避免重复处理。
- 招聘者在线状态筛选：支持在线、刚刚活跃、今日活跃、3日内活跃、本周活跃、本月活跃、半年前活跃等状态。
- 自动执行立即沟通：打开职位详情，检测在线状态后点击“立即沟通”。
- AI 职位判别：读取职位详情中的已知信息，结合当前配置版本的用户提示词请求 AI；AI 判断通过后才继续“立即沟通”。
- AI 判断结果：记录通过状态、分数、理由和风险；判断不通过时跳过职位。
- AI 返回约束：使用岗位匹配结果 JSON Schema，要求返回 `pass`、`score`、`reason`、`risks` 四个字段，并在本地再次校验。
- AI 异常处理：支持 AI 调用失败时跳过职位或允许继续。
- AI 模型选择：预置 `deepseek-v4-flash`、`deepseek-flash`、`deepseek-v4-pro`，并支持自定义模型名称。
- 弹窗处理：自动处理“留在此页”等确认操作。
- 投递控制：支持开始投递、暂停投递、继续投递和投递下一条。
- 悬浮操作面板：支持拖动、收起、展开和调整大小。
- 操作日志面板：显示在主悬浮窗右侧，记录职位筛选、投递、AI 判断、版本切换和异常状态，支持展开、收起、滚动查看和清空。

### 页面状态

- 配置面板已就绪
- 自动翻页中
- 正在点击投递
- 投递已暂停/已继续
- 岗位队列已完成
- 投递失败或职位被跳过

## 3. 聊天沟通页

### 页面目标

监听新的聊天会话，并按照用户配置的消息模板自动回复招聘者。

### 页面功能

- 当前配置版本展示：显示当前正在使用的配置版本名称。
- 配置版本切换：切换后使用对应版本的聊天模板进行自动回复。
- 聊天列表监听：实时监听新增会话和消息变化。
- 自动识别新消息：根据聊天内容变化识别需要处理的会话。
- 自动进入对应会话：检测到新消息后打开对应招聘者会话。
- 自动发送文字消息：支持连续发送多条文字消息。
- 自动发送图片消息：支持发送配置中的图片。
- 多轮消息发送：按照预设顺序组合发送文字和图片。
- 消息发送校验：确认会话、输入框、发送按钮和聊天记录均已就绪。
- 防重复回复：记录已处理招聘者，避免重复自动回复。
- 监听控制：支持开始沟通和取消监听。
- 当前模板预览：展示正在使用的文字和图片消息内容。
- 悬浮聊天面板：支持拖动、收起、展开和调整大小。
- 操作日志面板：显示聊天监听、自动回复、版本切换和异常状态，支持展开、收起、滚动查看和清空。

### 页面状态

- 聊天页面已就绪
- 已开始监听聊天列表
- 检测到新消息
- 正在自动回复
- 模板消息已发送
- 自动回复失败
- 已取消聊天监听

## 4. 设置页面

### 页面目标

统一管理多个配置版本，以及每个版本下的职位筛选条件、招聘者在线状态和自动聊天消息模板。

### 页面功能

#### 配置版本管理

- 查看配置版本列表。
- 新建配置版本。
- 编辑当前配置版本。
- 复制已有配置版本。
- 重命名配置版本。
- 删除配置版本。
- 设置默认配置版本。
- 切换当前使用的配置版本。
- 显示当前选中的版本状态。

版本名称示例：

- 上海前端
- 杭州 Node.js
- 远程岗位
- 高活跃招聘者

#### 版本切换规则

- 每个版本拥有独立的职位和聊天配置。
- 切换版本不会覆盖其他版本的内容。
- 切换版本后，职位列表页读取新版本的关键词、地点和筛选规则。
- 切换版本后，聊天页读取新版本的文字、图片和消息顺序。
- 正在执行投递或自动回复时，不允许直接切换版本，避免执行过程中配置发生变化。
- 切换版本前，如果当前版本有未保存修改，需要提示用户保存或放弃修改。
- 至少保留一个配置版本，不允许删除最后一个版本。

#### 职位筛选设置

- 设置职位关键词。
- 设置工作地点。
- 设置屏蔽词。
- 使用 `-` 分隔多个条件，留空表示不限。

#### 招聘者在线状态设置

- 选择“不限”或指定在线状态。
- 设置无法识别在线状态时的处理方式：跳过职位或允许继续。
- 自动检测当前页面是否支持在线状态字段。

#### 多轮聊天消息设置

- 添加文字消息。
- 添加图片消息。
- 编辑文字内容。
- 选择图片并显示文件名。
- 图片超过 1MB 时尝试压缩。
- 调整消息发送顺序。
- 删除消息。
- 保存消息模板。

#### 表单校验

- 校验在线状态选择是否完整。
- 校验当前页面是否支持在线状态筛选。
- 校验文字消息是否为空。
- 校验图片消息是否成功读取。

#### 配置持久化

- 所有配置版本保存在浏览器 `localStorage` 中。
- 刷新页面后版本列表、版本内容和当前选中版本仍然保留。
- 职位页和聊天页共用当前选中的配置版本。
- 版本内容修改后同步更新聊天页面的模板预览。

#### 设置操作

- 保存设置。
- 返回或取消修改。
- 放弃未保存内容前进行确认。

## 5. 页面关系

```text
设置页面
   │
   ├── 管理多个配置版本
   └── 当前版本
       ├── 提供职位关键词、地点、屏蔽词
       ├── 提供招聘者在线状态规则
       └── 提供文字和图片聊天模板
        │
        ├── 职位列表页：筛选职位并执行立即沟通
        └── 聊天沟通页：监听新消息并自动回复
```

## 6. 核心用户流程

1. 用户打开设置页面，创建或选择一个配置版本。
2. 用户配置该版本的职位条件和聊天模板。
3. 用户进入职位列表页，确认当前版本后点击“开始投递”。
4. 系统使用当前版本自动筛选职位并执行“立即沟通”。
5. 用户进入聊天沟通页，确认当前版本后点击“开始沟通”。
6. 系统使用当前版本监听新会话，并按对应模板自动发送消息。
7. 系统记录已处理会话，避免重复回复。
